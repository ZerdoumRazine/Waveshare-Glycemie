# Reading and maintaining WaveShare Glycémie

**English only**

This guide explains where the project's logic lives. Comments in `main/`,
`tools/`, and `tests/` describe module responsibilities and important
engineering decisions, especially failure paths. The implementation stays in
C, Python, PowerShell and CMake; **comments do not add functionality**.

For the full source-reading sequence, see the [developer walkthrough](DEVELOPER_WALKTHROUGH.md).

## Where to look

| Area | Main modules | Responsibility |
|---|---|---|
| Startup and shared state | `main/app_main.c`, `main/app_state.c` | Start tasks and publish consistent snapshots |
| Wi-Fi, Internet and clock | `main/wifi_manager.c`, `main/net_services.c` | Connectivity, TLS probes and SNTP |
| Dexcom Share | `main/dexcom_share.c`, `main/dexcom_guard.c` | Read Share and prevent repeated rejected logins |
| User setup | `main/credentials.c`, `main/ui_setup.c` | Trial new credentials before replacing known working ones |
| Glucose readings | `main/glucose_service.c`, `main/glucose_math.c` | Polling, deduplication and freshness |
| Touch UI | `main/ui_main.c`, `main/ui_*.c`, `main/ui_common.c` | Navigation, plots, readings, alerts and settings |
| Sensor, infusion set and stock | `main/sensor_session.c`, `main/consumables.c`, `main/stock.c` | Replacement times and reminders |
| Alerts and audio | `main/alerts.c`, `main/audio_out.c`, `main/voice.c` | Priority, beeps and offline WAV announcements |
| Languages | `main/i18n.c`, `tools/voice/langues_voix.py` | Screen translations and spoken phrases |
| microSD history | `main/sd_storage.c`, `tools/recuperer_microsd.py` | Daily files and recovery |
| Windows installation | `tools/installer.ps1`, `tools/assistant_config.py`, `tools/pc_app/` | Guarded flashing and USB setup |
| Tests and delivery | `tests/`, `.github/workflows/` | Regression checks and ESP-IDF builds |

## Comment conventions

- **File header:** describe what the module owns (English only).
- **Non-obvious function:** explain its intention, invariant, or failure-handling rule.
- **Inside a function:** comment a subtle decision, not every assignment.
- **Keep comments current:** inaccurate explanations are worse than short ones.

For example, `credentials_clear()` explicitly persists an empty record
before cleaning up account-related state. Its comment explains why this avoids
the reappearance of credentials embedded by an older personal firmware.

## Verify changes

```powershell
python tests/run_tests.py
python tests/test_depot.py
python tests/test_assistant_config.py
python tests/test_sd_voice_upload.py
```

Host tests run without hardware; they are **not a substitute** for ESP-IDF
compilation or physical validation. GitHub Actions runs the C/Python suites
and builds the public firmware.

## Deliberately untouched sources

- `components/esp_driver_ppa/` derives from Espressif. Preserve the upstream
  Apache-2.0 notices, copyright statements and modification record.
- `main/voice_clips.h` is generated by `tools/voice/pack_voice.py`.
  Hand-edited comments would disappear during regeneration.
- Binaries, screenshots, fonts and resource manifests are not source
  code that benefits from per-function commentary.

This is an **experimental supplementary glucose display**, not certified
for medical use. Never rely on its values or alerts instead of official
Dexcom monitoring or to decide on treatment.
